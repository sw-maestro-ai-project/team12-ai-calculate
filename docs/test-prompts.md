# 개선점 검증용 테스트 프롬프트

> Streamlit UI(http://localhost:8501)에서 순서대로 입력해 각 기능이 정상 동작하는지 확인한다.
> 각 테스트는 **대화 초기화** 후 시작한다 (좌측 사이드바 🗑️ 버튼).

---

## 테스트 1 — 피드백 의도 분류: modify_exception (잘 안됨) -> (해결)

**목적**: 기존 계산에 조건을 추가했을 때 정상 반영 확인

**[1번째 입력]**

```
A, B, C, D 네 명이서 8만원 냈어. 주류 3만원, 안주 5만원.
```

→ 기대: EXCEPTION 또는 SIMPLE 결과 (예외 없으면 SIMPLE)

**[2번째 입력]**

```
D가 술을 전혀 안 마셨어
```

→ 기대:

- 전략 배지가 `⚡ 예외 조건 반영`으로 변경
- D의 금액이 낮아짐
- `계산 근거 보기`에 D 감액 로그 포함

---

## 테스트 2 — 피드백 의도 분류: reset

**목적**: 피드백 중 "처음부터"라고 하면 새 정산으로 전환 확인

**[1번째 입력]**

```
A, B, C 세 명이서 6만원 균등 분배야
```

**[2번째 입력]**

```
아 잠깐, 그거 말고 완전히 다른 상황이야. 처음부터 다시 할게. E, F, G 세 명이서 9만원인데 주류 5만원, 안주 4만원이야. G가 술을 안 마셨어.
```

→ 기대:

- A, B, C가 아닌 E, F, G로 새 계산됨
- G가 주류에서 완전 제외된 EXCEPTION 결과

---

## 테스트 3 — 피드백 의도 분류: complaint + 자가 진단

**목적**: 모호한 불만 입력 시 되묻기 메시지 + 자가 진단 확인

**[1번째 입력]**

```
A, B, C, D 네 명이서 8만원. 주류 3만원, 안주 5만원. D는 술 미섭취. C는 20분 지각했고 지각비는 5000원이야.
```

→ 기대: EXCEPTION 결과. C 할증, D 감액 반영

**[2번째 입력]**

```
계산이 좀 이상한 것 같은데?
```

→ 기대:

- 계산 결과가 새로 나오지 않음
- `💬` 말풍선으로 자가 진단 메시지 출력
- 메시지 안에 "하한선" 또는 "할증" 등 실제 규칙이 언급됨

---

## 테스트 4 — 최종 금액 직접 지정 (fixed_amount)

**목적**: "A는 얼마만 내"처럼 직접 금액을 지정했을 때 강제 적용 확인

**[1번째 입력]**

```
A, B, C, D 네 명이서 10만원 균등 분배야
```

**[2번째 입력]**

```
A는 사정이 있어서 2만원만 내게 해줘
```

→ 기대:

- A의 최종 금액이 20,000원으로 고정
- 나머지 B, C, D가 합쳐서 80,000원이 됨
- 계산 근거에 fixed_amount 반영 확인 (30% 하한선 미적용)

---

## 테스트 5 — 피드백 이력 충돌 해소

**목적**: 앞 지시와 뒤 지시가 충돌할 때 최신 지시 우선 확인

**[1번째 입력]**

```
A, B, C 세 명이서 9만원. 주류 5만원, 안주 4만원.
```

**[2번째 입력]**

```
A는 1만원만 내게 해줘
```

→ 기대: A = 10,000원 고정

**[3번째 입력]**

```
A 고정 취소하고 다들 똑같이 내게 해줘
```

→ 기대:

- A가 다시 균등 금액으로 복귀
- 세 명이 동일 금액 (또는 예외 조건에 따라 재계산)

---

## 테스트 6 — 변경 사항 하이라이트 (잘 안됨)

**목적**: 피드백 후 무엇이 바뀌었는지 직전 결과 대비 변동 표시 확인

**[1번째 입력]**

```
A, B, C, D 네 명이서 8만원. 주류 3만원, 안주 5만원.
```

**[2번째 입력]**

```
B가 안주를 절반 정도만 먹었어
```

→ 기대:

- 결과 위에 `✏️ 직전 결과 대비 변경` 섹션 표시
- `B: X원 → Y원 (−Z원)` 형태의 변동 내역

---

## 테스트 7 — reset guard (참여자 오분류 방지)

**목적**: 피드백인데 참여자가 절반 이상 달라지면 자동 새 정산 전환 확인

**[1번째 입력]**

```
가나다라 네 명이서 8만원 균등 분배야
```

**[2번째 입력]** ← 명시적 reset 없이 완전히 다른 상황 입력

```
마바사아자 다섯 명이서 15만원인데, 주류 8만원, 안주 7만원이야. 아가 술을 안 마셨어.
```

→ 기대:

- 가나다라가 아닌 마바사아자로 새 계산됨
- EXCEPTION 결과 (아 = 주류 감액)

---

## 테스트 8 — target_items 동의어 정규화

**목적**: LLM이 항목명을 "술"이라고 써도 "주류"로 자동 교정 확인

**[1번째 입력]**

```
A, B, C, D 네 명이서 8만원. 주류 3만원, 안주 5만원. D는 술을 전혀 안 마셨어.
```

→ 기대:

- D가 주류(3만원)에서 완전 제외된 EXCEPTION 결과
- safety_error 없이 정상 통과 (LLM이 "술"로 파싱해도 "주류"로 교정됨)

---

## 테스트 9 — target_items 오기 차단 (safety_error) (잘 안됨)

**목적**: 동의어 정규화로도 매핑 안 되는 항목명은 safety_error로 차단 확인

**[1번째 입력]**

```
A, B, C, D 네 명이서 8만원. 주류 3만원, 안주 5만원. D는 택시비를 안 냈어.
```

→ 기대:

- `⚠️ safety_error` 경고 박스 표시
- "예외 조건의 항목 이름이 입력한 비용 항목과 일치하지 않습니다" 메시지
- 정확한 항목명 재입력 안내

---

## 테스트 10 — SPONSOR: 선결제 (전액)

**목적**: 한 명이 전액 선결제 시 송금 안내 생성 확인

**[1번째 입력]**

```
A, B, C, D 네 명이서 8만원. 주류 3만원, 안주 5만원. D는 술 미섭취. A가 전액 카드로 긁었어.
```

→ 기대:

- `💳 선결제 정산` 배지
- A 카드에 `💳 80,000원 선결제` 노트
- 송금 안내 섹션: `B ──▶ A`, `C ──▶ A`, `D ──▶ A` 금액 표시
- `✅ 선결제로 완전 정산` 표시

---

## 테스트 11 — SPONSOR: 선결제 (일부)

**목적**: 선결제 금액이 총액보다 적을 때 미정산 잔액 경고 확인

**[1번째 입력]**

```
A, B, C 세 명이서 6만원. A가 2만원 먼저 냈어.
```

→ 기대:

- `💳 선결제 정산` 배지
- 송금 안내 섹션에 일부 송금 내역
- `⚠️ 미정산 잔액 N원 (현장 결제분)` 경고

---

## 테스트 12 — SPONSOR: 지원금 (subsidy)

**목적**: 외부 지원금이 있을 때 정산 대상액 축소 확인

**[1번째 입력]**

```
A, B, C, D 네 명이서 10만원. 동아리에서 2만원 지원받았어.
```

→ 기대:

- `💳 선결제 정산` 배지
- `🎟️ 지원금 20,000원 반영 (정산 대상액 80,000원)` 안내
- 각자 약 20,000원씩 부담
